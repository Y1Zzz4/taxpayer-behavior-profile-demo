# 12366来电画像与坐席服务辅助系统

本项目用于验证12366来电数据的号码级整合、历史画像构建和坐席服务辅助效果，覆盖涉税费咨询、信息查询、服务投诉、违法举报、意见建议等服务场景。

系统从 Excel 导入历史来电，形成号码画像和单通来电轨迹。模拟新来电时，坐席可以先看到关键历史信息，再获得基于该号码历史实时生成的个性化接待建议。

## 主要功能

- 读取单日或多日 Excel，并支持后续新文件增量导入；
- 保存每通来电的原始登记信息和结构化分析结果；
- 按号码汇总咨询主体、细化主体、专题类别、需求类别、熟练度、未解决事项和服务效果；
- 将来电需求归入政策咨询、操作辅导、工单/拉起、涉税查询、系统异常、投诉举报、意见建议或其他类别；
- 输入来电号码后，优先展示近5个工作日的关键信息和完整历史画像；
- 根据号码历史实时生成接待策略，建议不写入数据库；
- 分页查看历史来电，并进入单条记录查看原始信息和关键分析结果；
- 通过图表查看画像规模、主体构成、熟练度、服务画像、来电趋势，以及各专题/需求类别的解决情况；
- 将号码画像、来电轨迹和更新摘要导出为 Excel。

系统生成的是服务过程辅助信息，不提供具体税费政策答案，不用于执法判断、税收风险认定或坐席绩效评价。

## 快速开始

环境要求：Python 3.10 或以上，可访问 OpenAI 兼容的大模型接口。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

复制 `.env.example` 为 `.env`，配置模型和本地数据保护参数：

```text
LLM_BASE_URL=大模型接口地址
LLM_API_KEY=大模型密钥
LLM_MODEL=模型名称
PHONE_HASH_KEY=号码查询哈希密钥
PHONE_ENCRYPTION_KEY=号码加密密钥
DATABASE_PATH=data/database/taxpayer_profiles.sqlite3
```

可以生成本地号码保护密钥：

```bash
.venv/bin/python scripts/generate_local_secrets.py
```

使用演示数据构建数据库：

```bash
.venv/bin/python scripts/init_database.py data/raw/smoke_test.xlsx \
  --database data/database/smoke_test_realtime.sqlite3
```

启动服务：

```bash
.venv/bin/python scripts/run_demo.py \
  --database data/database/smoke_test_realtime.sqlite3
```

浏览器访问 `http://127.0.0.1:8000`。端口被占用时可增加 `--port 8001`。

## 页面说明

- `来电服务工作台`：输入号码后即时展示历史信息，随后生成本次接待建议；
- `画像数据概览`：查看当前画像库的结构、趋势、服务特征及分类事项解决占比；
- `画像推演中心`：回放画像证据链，并通过只读场景演示画像和服务方式的增量变化；
- `历史来电记录`：分页查看来电轨迹，点击一条记录可查看原始登记信息和分析结果。

工作台中的“信息速览”以数据库内最新来电日期为基准，只统计最近5个工作日，并明确标注“仅供参考”。点击服务画像类型可以查看本号码的命中依据和完整判定优先级。模型未在交互时限内返回时，历史画像仍可正常查看，页面会显示规则辅助建议。

## 输入数据

Excel 至少应包含：

- `业务编号`
- `来电号码`
- `登记日期`

系统会保存原始数据 A—P 列：

```text
业务编号、转写结果、登记日期、通话开始时间、通话结束时间、坐席工号、坐席姓名、
业务内容、答复内容、录音路径、登记单位、登记处理方式、业务类别、来电号码、满意度、呼叫流水号
```

如输入中存在 `大模型核心问题` 和 `一级专题类别`，系统会将其作为可直接使用的事实字段。人工登记的业务内容和答复内容优先用于确定主问题、答复及办理路径，转写内容用于补充对话过程、有效问答和服务信号。

来电号码不限制固定位数。常见空格、横线和括号会在安全匹配前统一处理。

## 增量导入

导入一个新的 Excel：

```bash
.venv/bin/python scripts/update_database.py data/raw/new_calls.xlsx \
  --database data/database/smoke_test_realtime.sqlite3
```

同一文件会通过文件指纹跳过，同一业务编号不会重复写入。新增记录会按时间顺序并入已有画像。

## 服务画像分类

系统为每个号码生成一个可解释的服务画像类型，用于帮助坐席选择沟通方式。分类按以下优先级判断：

1. `服务关注型`：历史存在对本通热线服务不满记录；
2. `事项待跟进型`：存在未直接解决事项或工单；
3. `持续咨询型`：存在重复事项，或累计来电达到3次；
4. `引导辅助型`：历史业务熟练度低于5分；
5. `熟练自主型`：历史业务熟练度达到8分；
6. `初次咨询型`：当前仅有一次历史来电；
7. `常规咨询型`：暂未出现以上稳定服务特征。

每个画像同时保存分类依据。该分类会随来电增量更新，仅用于服务准备，不代表纳税信用、风险等级或人员评价。

## 数据存储与保护

SQLite 使用三张核心表：

- `caller_profiles`：号码级历史画像；
- `call_trajectories`：单通来电的原始登记信息和结构化轨迹；
- `update_logs`：文件批次及处理结果。

来电号码使用 HMAC 建立查询索引，并使用 Fernet 加密保存。发送给大模型的文本会先处理常见号码、身份证号、社会信用代码、邮箱和账号信息。前端历史列表及详情仅展示脱敏号码，录音路径只作为文本展示。

数据库包含转写、业务内容、答复内容等敏感业务数据，应存放在受控环境中。`.env`、原始数据、数据库和导出结果不会提交到代码仓库。

## 导出与测试

导出结果：

```bash
.venv/bin/python scripts/export_results.py \
  --database data/database/smoke_test_realtime.sqlite3 \
  --output data/output/taxpayer_profiles.xlsx
```

导出文件包含完整来电号码和原始登记信息，应按敏感数据管理。

运行测试：

```bash
.venv/bin/python -m pytest -q
```

## 使用边界

- 当前版本用于单机演示和效果验证；
- 一个来电号码对应一个历史画像；
- 大模型提取和服务建议需要结合实际业务判断；
- 具体政策答复应接入独立、可追溯的政策知识服务；
- 正式部署前应补充账号权限、访问审计和敏感信息展示控制。
